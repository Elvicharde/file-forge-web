01 / MOTIVATION & PROBLEM SPACE

Why build another filesystem CLI?

Shell scripts are brittle across developer workstations. When writing multi-platform automation, teams face stark inconsistencies between BSD utilities on macOS, GNU coreutils on Linux, and PowerShell or cmd.exe under Windows.

Beyond naive shell wrappers

Most custom scripts rely on ad-hoc child_process.exec() calls that wrap standard shell binaries. This pattern creates security vulnerabilities through command injection, breaks when OS distributions omit flags like -r or -P , and fails to offer structured telemetry.

fileForge was architected as an exploration in clean systems engineering. Built strictly on top of Node.js node:fs/promises and node:path , it establishes isolated compilation boundaries between command line input tokenization, semantic schema validation, and native platform I/O.

Core Tenet

Deterministic I/O Safety

Every write, move, and recursive deletion is bounded by an pre-flight stat checks. When an error occurs, the process emits typed error contracts rather than terminating in unstructured stacktrace leaks.

02 / COMMAND SPECIFICATION

Currently Implemented Commands

fileForge ships with core POSIX-familiar filesystem primitives implemented natively in modern Node.js.

ls List Directory Content
STABLE

Scans target directory, aggregates detailed filesystem stat metadata (POSIX permissions string, numeric UID/GID, formatted byte sizes, and timestamps).

-a, --all Include hidden files matching .*
-l, --long Emit tabular metadata representation
-h, --human Display byte values in base-2 units (KB, MB, GB)
fileforge ls -a -l ./src
cp Copy Files & Trees
STABLE

Transfers files or complete recursive subtrees using high-throughput pipeline streams, with safety guards to avert unintended file clobbering.

-r, -R, --recursive Copy directories recursively
-n, --no-clobber Never overwrite existing destination file
-f, --force Force overwrite unlinking read-only descriptors
fileforge cp source.txt projects/source.txt
mv Move & Rename Atomic
STABLE

Performs atomic inode rename operations across compatible device mounts, with automatic fallback to streaming copy-and-unlink on cross-device boundary transitions ( EXDEV ).

-n, --no-clobber Abort transaction if destination file exists
-v, --verbose Emit detailed atomic stage lifecycle confirmations
fileforge mv old.txt new.txt
mkdir Directory Creation
STABLE

Creates directory leaves or arbitrary recursive trees. Automatically handles ancestor resolution and validates target path read/write privileges before initiating filesystem mutations.

-p, --parents Make parent directories without throwing if present
-m, --mode <octal> Specify POSIX file permissions mode (default: 0755)
fileforge mkdir -p projects/api/v1
rm Safe Node Removal
DRY-RUN READY STABLE

Unlinks files or deletes nested recursive hierarchies. Features mandatory dry-run verification mode to preview paths marked for deletion prior to actual disk unlinking.

-r, -R, --recursive Recursively remove hierarchies
-f, --force Ignore nonexistent files & prompt overrides
--dry-run Output targets without disk unlinking
fileforge rm --dry-run unwanted.txt

06 / ENGINEERING CASE STUDY

Built to be extended: Core Architectural Decisions

An in-depth look into the architectural trade-offs, modular design patterns, and engineering choices that define the fileForge core.

Decision 01

Independent Command Definitions

Every command implements a strict TypeScript contract specifying positional arguments, expected flags, usage schemas, and a discrete execute() method. No command possesses ambient state or cross-command dependencies.

Interface: ICommandDefinition<T>
Decision 02

Central Command Registry

Commands register into an immutable registry via declarative keys. This decoupling makes it trivial to mount custom plugins or third-party extensions in future releases without modifying core runner logic.

Pattern: Registry.register(cmd)
Decision 03

Strict Argument Tokenization

Arguments and flags are validated against command schemas before execution starts. Unrecognized flags trigger immediate validation rejections with suggested alternatives, preventing dangerous partial mutations.

Safety: Zero Early Side-Effects
Decision 04

Filesystem Layer Abstraction

Direct invocations of Node.js fs are isolated to a single adapter layer. Path strings are validated for traversal vulnerabilities ( ../.. ) and normalized across operating systems automatically.

Abstraction: FSAdapter / VirtualFS
Decision 05

Typed Error Hierarchy

Raw POSIX system errors ( ENOENT , EEXIST , EACCES ) are intercepted and translated into typed FileForgeError instances containing actionable remediation advice.

Diagnostics: Clean CLI Exits
Decision 06

Zero Heavy Dependencies

By deliberate design, fileForge rejects heavy external dependencies. Command parsing, colors, and directory traversing utilize pure built-in Node.js primitives, guaranteeing instant CLI startup times.

Performance: < 45ms Boot Time
